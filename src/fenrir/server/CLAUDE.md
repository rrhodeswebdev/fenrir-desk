# src/fenrir/server/

The FastAPI shell and the state behind its APIs. API shapes in `docs/contracts.md` (Plans 11–16).

- Entry points: `app.py` (`create_app(settings, session_key, launch_code, static_dir, *, port, dev)`: `HostGuard` middleware runs before routing on every HTTP and WebSocket request, 400 for a non-loopback or repeated Host, 307 from `127.0.0.1` to `localhost`; single-use `GET /launch?code=` sets the cookie and 303s to `/`; `GET /api/health`; SPA catch-all registered last, never for `api/` or `ws/` (`ValueError` at startup if `static_dir` has no `index.html`); pure `host_action`, `localhost_url`, `static_file`); `jobs.py` (pure backtest-job state: `Job`, `JobItem`, `new_job`, `update_item`, `unfinished`, `restart`, `progress_step`, `to_json`/`from_json`); `jobs_runner.py` (`JobRunner(settings, *, child=CHILD, secret="", idle=1800, expand_timeout=60, describe_timeout=30)`: `start()` loads `data/jobs/*.json` through `read_regular` (skips and logs a bad file, a symlink, a non-regular file or one over 16 MiB) and re-queues unfinished items, `stop()` kills the running child's process group and any expand or describe child, `expand(strategies, accounts, contracts)` expands a grid in an isolated child (ValueError with its error), `describe(paths)` loads strategy files in an isolated child for `GET /api/strategies` (never raises for a child failure: each undescribed file, or one described twice or with a hash not the bytes the server read first, gets `error`; the server hashes each file before the child runs, through `_strategy_hash` (`fenrir.files.read_regular`): regular files of at most 1 MiB only, never a symlink or FIFO, which never reach the child; ValueError, nothing hashed, while `strategies_dir` itself is a symlink (`fenrir.files.refuse_symlink`, also used by `GET /api/strategies` and `GET /api/backtests/options`)), `submit`, `jobs()` newest first, `get`, `add_listener`/`remove_listener` (called with `to_json(job)` on every change, from the runner thread); one runner thread, ONE child per job; child output is untrusted: pure `parse_event`, `parse_grid`, `parse_description`, plus `strategy_user`); `job_child.py` (`python -P -m fenrir.server.job_child [--expand|--describe]`: runs one job's items via `cached_run`, or `expand_grid`, or `load_strategy` per file, JSON lines on stdout; every `--expand` glob match and every job item must resolve to a regular file inside `strategies_dir` before anything loads, #153); `auth.py` (pure `session_ok`, `allowed_origins`, `origin_ok`, `csrf_ok`; FastAPI glue `require_session` for every `/api` router, `check_ws` for every `/ws/*` handler before `accept()`, else `await ws.close()` and return); `terminal.py` (pure PTY core: `child_env(env, secret)` drops every `FENRIR_*` var and any var whose value holds a non-empty `secret`, sets `TERM`; `shell_argv(env, platform)`; `parse_message(text) -> Input | Resize | None` for client frames `{"type":"input","data":str}` / `{"type":"resize","cols":int,"rows":int}`, sizes clamped to 1–1000); `ptyproc.py` (shell: `spawn(argv, env, as_user)` → a PTY with async `read()` (b"" at EOF), `write(bytes)`, `resize(cols, rows)`, `close()`; POSIX `pty.openpty` + `Popen` in a new session with the PTY as controlling tty, read via `loop.add_reader`; Windows pywinpty; starts in the server's cwd at 80×24; OSError, or SubprocessError when TIOCSCTTY fails, when the shell cannot start; with `as_user` the PTY slave is chowned to that user; `close()` hangs up, gives the shell 1 s to SIGHUP its jobs, then SIGKILLs its process group and every live process in its session, re-listing until it is empty (`_sweep`: `KILL_ROUNDS` = 10, logged past that; a pid that raises PermissionError is skipped and logged; `_session_pids`: `/proc` skipping zombies on Linux, `/bin/ps` on macOS, `[]` logged if `ps` cannot run; job control gives each job its own group) and reaps it, all in one thread so a cancelled `close()` still finishes; Windows `close()` terminates only the shell, untested).
- Isolation (DEC-1): `isolation.py`: pure `check(euid, pty_user_uid, pty_user_gid, private_dir_stat, private_dir_path, private_dir_real, app_roots, env_file_path=None, env_file_real=None) -> list[str]`; shell `isolation_problems(settings)` gathers the facts (private dir judged as configured: `absolute()` + `lstat`, never resolved first) and is `[]` unless `FENRIR_BIND_ALL=1`. `fenrir serve` refuses to start when binding all interfaces with any problem, else logs each; the terminal, strategy children (`jobs_runner.strategy_user`) and `PullRunner.start` refuse when it is non-empty. Shell `as_user(user)` → (env overlay, `Popen` kwargs) drops a child to `user` (`user`, `group`, `extra_groups=[]`, passwd `HOME`/`USER`/`LOGNAME`/`SHELL`); used by job children and the terminal; KeyError for no such user.
- Auth state: `auth.py` reads `app.state.session_key: str` and `app.state.allowed_origins: frozenset[str]` (from `allowed_origins(port, dev)`); `create_app` sets both, plus `app.state.settings`, `app.state.pull` and `app.state.jobs` (`JobRunner(settings, secret=session_key)`, started and stopped by the app's lifespan, so `fenrir serve` never leaves a job child behind). new `/api` routers go in `create_app` above the SPA catch-all with `dependencies=[Depends(require_session)]`. Cookie name: `fenrir_session` (`SESSION_COOKIE`).
- Data pulls: `pull.py` runs `fenrir data pull` as a child process, one at a time, for `POST /api/data/pull` (`routes/data.py`). `create_app` holds one on `app.state.pull` (idle until a POST): `PullRunner(pull_command(), pull_env(os.environ, settings), settings=settings)`: `start() -> bool` (False while one runs → 409; ValueError, nothing started, when the image fails the isolation check → 500), `status()` → `{state: "idle"|"running"|"done"|"error", started_at, finished_at, returncode, log_tail}` (last 20 lines of stdout+stderr, each clipped to 500 chars, in memory). Neither waits on the child, so both are safe on the event loop. The child runs with `python -P` (cwd off `sys.path`, so repo files cannot shadow `fenrir`) and gets the parent env minus `FENRIR_NT_TOKEN` and `FENRIR_ENV_FILE`, plus the LSE key and `FENRIR_DATA_DIR`. It runs as the server's user (root in the image), never as `FENRIR_PTY_USER`, which could read the LSE key from `/proc/<pid>/environ` of a child it owns; `data/` is terminal-writable, so the store's writes are symlink-safe instead (DEC-1, #135, `src/fenrir/data/CLAUDE.md`).
- Routes: `routes/<area>.py`, each a `router` registered in `create_app` (see `routes/CLAUDE.md`). `routes/rules.py` (Plan 15): `GET /api/rules`, `GET`/`PUT /api/rules/{id}`; pure `staleness(verified_on, today)`; 404 for an id with no file, 422 `{detail, errors: [{loc, msg}]}` for a non-object body, a schema error, a rename (`["account"]`) or a broken file on disk; saves through `rules.writer.write_account`. `routes/data.py` (16.2): `GET /api/data`, `POST /api/data/pull`. `routes/backtests.py` (14.3): `/api/backtests/{options,jobs,jobs/{id},results,results/{key},compare}` and `WS /ws/jobs` (its own `ws_router`, no `require_session`); `routes/terminal.py` (13.2): `WS /ws/terminal`, registered without `require_session`; `check_ws` and, in the image, `isolation_problems` before `accept()` (refused → 403, the reasons logged); one PTY per connection running `shell_argv` with `child_env(os.environ, session_key)` plus `as_user(FENRIR_PTY_USER)` (no such user → 403, logged); input is buffered and written by its own task so a disconnect is always seen (one frame over `MAX_PENDING` = 1 MiB, or more than that queued behind a blocked write → close 1009; about 2 MiB held at most); unexpected task errors are logged. Only a `setsid` process outlives a disconnect, as the PTY user. `routes/settings.py` (24.2): `GET`/`PUT /api/settings` (the secrets file `env_file_path(os.environ)`, read fresh, written temp + rename mode 0600; secrets masked, a mask sent back is unchanged), `POST /api/settings/import-repo-secrets` (the repo `.env`'s two secrets into the secrets file where empty, image only) and `GET`/`PUT /api/settings/accounts` (`<data_dir>/accounts.yaml`, merged). `routes/strategies.py` (23.4): `GET /api/strategies`, names listed here, loaded by `jobs.describe`, one load at a time (409 while busy).
- Pure vs shell: `jobs.py`, `terminal.py`, `isolation.check`, the `auth.py` predicates and `pull.py`'s `pull_status`, `pull_command`, `pull_env` are pure. `app.py` is glue around its pure helpers. Strategy code never runs in the server process (DEC-1): never call `load_strategy` or `expand_grid` here; grid expansion, strategy descriptions and backtest jobs run in `job_child` with `terminal.child_env`, as `FENRIR_PTY_USER` when set, in its own session. Later: the remaining routes (plans 13–16).
- Not here: running a backtest or the grid itself (`src/fenrir/backtest/`), rule logic (`src/fenrir/rules/`), the web UI (`web/`).
- Tests: `tests/server/`.
