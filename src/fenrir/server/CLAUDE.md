# src/fenrir/server/

The FastAPI shell and the state behind its APIs. API shapes in `docs/contracts.md` (Plans 11–16).

- Entry points: `app.py` (`create_app(settings, session_key, launch_code, static_dir, *, port, dev)`: `HostGuard` middleware runs before routing on every HTTP and WebSocket request, 400 for a non-loopback or repeated Host, 307 from `127.0.0.1` to `localhost`; single-use `GET /launch?code=` sets the cookie and 303s to `/`; `GET /api/health`; SPA catch-all registered last, never for `api/` or `ws/` (`ValueError` at startup if `static_dir` has no `index.html`); pure `host_action`, `localhost_url`, `static_file`); `jobs.py` (pure backtest-job state: `Job`, `JobItem`, `new_job`, `update_item`, `unfinished`, `restart`, `progress_step`, `to_json`/`from_json`); `jobs_runner.py` (`JobRunner(settings, *, child=CHILD, secret="", idle=1800, expand_timeout=60)`: `start()` loads `data/jobs/*.json` (skips and logs a bad file) and re-queues unfinished items, `stop()` kills the running child's process group, `expand(strategies, accounts, contracts)` expands a grid in an isolated child (ValueError with its error), `submit`, `jobs()` newest first, `get`, `add_listener`/`remove_listener` (called with `to_json(job)` on every change, from the runner thread); one runner thread, ONE child per job; child output is untrusted: pure `parse_event`, `parse_grid`, plus `strategy_user`); `job_child.py` (`python -P -m fenrir.server.job_child [--expand]`: runs one job's items via `cached_run`, or `expand_grid`, JSON lines on stdout); `auth.py` (pure `session_ok`, `allowed_origins`, `origin_ok`, `csrf_ok`; FastAPI glue `require_session` for every `/api` router, `check_ws` for every `/ws/*` handler before `accept()`, else `await ws.close()` and return); `terminal.py` (pure PTY core: `child_env(env, secret)` drops every `FENRIR_*` var and any var whose value holds a non-empty `secret`, sets `TERM`; `shell_argv(env, platform)`; `parse_message(text) -> Input | Resize | None` for client frames `{"type":"input","data":str}` / `{"type":"resize","cols":int,"rows":int}`, sizes clamped to 1–1000).
- Isolation (DEC-1): `isolation.py`: pure `check(euid, pty_user_uid, pty_user_gid, private_dir_stat, private_dir_path, private_dir_real, app_roots, env_file_path=None, env_file_real=None) -> list[str]`; shell `isolation_problems(settings)` gathers the facts (private dir judged as configured: `absolute()` + `lstat`, never resolved first) and is `[]` unless `FENRIR_BIND_ALL=1`. `fenrir serve` logs each problem; the terminal, strategy children (`jobs_runner.strategy_user`) and the pull child (`pull.pull_user`) refuse when it is non-empty. Shell `as_user(user)` → (env overlay, `Popen` kwargs) drops a child to `user` (`user`, `group`, `extra_groups=[]`, passwd `HOME`/`USER`/`LOGNAME`/`SHELL`); shared by job and pull children.
- Auth state: `auth.py` reads `app.state.session_key: str` and `app.state.allowed_origins: frozenset[str]` (from `allowed_origins(port, dev)`); `create_app` sets both, plus `app.state.settings` and `app.state.pull`. new `/api` routers go in `create_app` above the SPA catch-all with `dependencies=[Depends(require_session)]`. Cookie name: `fenrir_session` (`SESSION_COOKIE`).
- Data pulls: `pull.py` runs `fenrir data pull` as a child process, one at a time, for `POST /api/data/pull` (`routes/data.py`). `create_app` holds one on `app.state.pull` (idle until a POST): `PullRunner(pull_command(), pull_env(os.environ, settings), settings=settings)`: `start() -> bool` (False while one runs → 409; ValueError, nothing started, when the image fails the isolation check → 500), `status()` → `{state: "idle"|"running"|"done"|"error", started_at, finished_at, returncode, log_tail}` (last 20 lines of stdout+stderr, each clipped to 500 chars, in memory). Neither waits on the child, so both are safe on the event loop. The child runs with `python -P` (cwd off `sys.path`, so repo files cannot shadow `fenrir`) and gets the parent env minus `FENRIR_NT_TOKEN` and `FENRIR_ENV_FILE`, plus the LSE key and `FENRIR_DATA_DIR`. With `FENRIR_BIND_ALL=1` it runs as `FENRIR_PTY_USER` (`pull_user`), since `data/` is terminal-writable (DEC-1, #135); natively as the server's user.
- Routes: `routes/<area>.py`, each a `router` registered in `create_app` (see `routes/CLAUDE.md`). `routes/rules.py` (Plan 15): `GET /api/rules`, `GET`/`PUT /api/rules/{id}`; pure `staleness(verified_on, today)`; 404 for an id with no file, 422 `{detail, errors: [{loc, msg}]}` for a non-object body, a schema error, a rename (`["account"]`) or a broken file on disk; saves through `rules.writer.write_account`. `routes/data.py` (16.2): `GET /api/data`, `POST /api/data/pull`.
- Pure vs shell: `jobs.py`, `terminal.py`, `isolation.check`, the `auth.py` predicates and `pull.py`'s `pull_status`, `pull_command`, `pull_env` are pure. `app.py` is glue around its pure helpers. Strategy code never runs in the server process (DEC-1): never call `load_strategy` or `expand_grid` here; grid expansion and backtest jobs run in `job_child` with `terminal.child_env`, as `FENRIR_PTY_USER` when set, in its own session. Later: PTY process and the remaining routes (plans 13–16).
- Not here: running a backtest or the grid itself (`src/fenrir/backtest/`), rule logic (`src/fenrir/rules/`), the web UI (`web/`).
- Tests: `tests/server/`.
