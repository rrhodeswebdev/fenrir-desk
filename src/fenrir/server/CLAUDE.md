# src/fenrir/server/

The FastAPI shell and the state behind its APIs. API shapes in `docs/contracts.md` (Plans 11–16).

- Entry points: `app.py` (`create_app(settings, session_key, launch_code, static_dir, *, port, dev)`: `HostGuard` middleware runs before routing on every HTTP and WebSocket request, 400 for a non-loopback or repeated Host, 307 from `127.0.0.1` to `localhost`; single-use `GET /launch?code=` sets the cookie and 303s to `/`; `GET /api/health`; SPA catch-all registered last, never for `api/` or `ws/` (`ValueError` at startup if `static_dir` has no `index.html`); pure `host_action`, `localhost_url`, `static_file`); `jobs.py` (pure backtest-job state: `Job`, `JobItem`, `new_job`, `update_item`, `unfinished`, `restart`, `progress_step`, `to_json`/`from_json`); `auth.py` (pure `session_ok`, `allowed_origins`, `origin_ok`, `csrf_ok`; FastAPI glue `require_session` for every `/api` router, `check_ws` for every `/ws/*` handler before `accept()`, else `await ws.close()` and return); `terminal.py` (pure PTY core: `child_env(env, secret)` drops every `FENRIR_*` var and any var whose value holds a non-empty `secret`, sets `TERM`; `shell_argv(env, platform)`; `parse_message(text) -> Input | Resize | None` for client frames `{"type":"input","data":str}` / `{"type":"resize","cols":int,"rows":int}`, sizes clamped to 1–1000).
- Auth state: `auth.py` reads `app.state.session_key: str` and `app.state.allowed_origins: frozenset[str]` (from `allowed_origins(port, dev)`); `create_app` sets both, plus `app.state.settings`. New `/api` routers go in `create_app` above the SPA catch-all with `dependencies=[Depends(require_session)]`. Cookie name: `fenrir_session` (`SESSION_COOKIE`).
- Data pulls: `pull.py` runs `fenrir data pull` as a child process, one at a time, for `POST /api/data/pull` (16.2). `PullRunner(pull_command(), pull_env(os.environ, settings.lse_api_key))`: `start() -> bool` (False while one runs → 409), `status()` → `{state: "idle"|"running"|"done"|"error", started_at, finished_at, returncode, log_tail}` (last 20 lines of stdout+stderr, each clipped to 500 chars, in memory). Neither waits on the child, so both are safe on the event loop. The child runs with `python -P` (cwd off `sys.path`, so repo files cannot shadow `fenrir`) and gets the parent env minus `FENRIR_NT_TOKEN`, plus the LSE key.
- Routes: `routes/<area>.py`, each a `router` registered in `create_app`. `routes/rules.py` (Plan 15): `GET /api/rules`, `GET`/`PUT /api/rules/{id}`; pure `staleness(verified_on, today)`; 404 for an id with no file, 422 `{detail, errors: [{loc, msg}]}` for a non-object body, a schema error, a rename (`["account"]`) or a broken file on disk; saves through `rules.writer.write_account`.
- Pure vs shell: `jobs.py`, `terminal.py`, the `auth.py` predicates and `pull.py`'s `pull_status`, `pull_command`, `pull_env` are pure. `app.py` is glue around its pure helpers. Later: `jobs_runner.py` (`JobRunner`: `data/jobs/<id>.json`, worker thread, WebSocket listeners; plan 14), `fenrir serve` and `session.key` (11.3/11.5), PTY process and routes (plans 13–16).
- Not here: running a backtest or the grid itself (`src/fenrir/backtest/`), rule logic (`src/fenrir/rules/`), the web UI (`web/`).
- Tests: `tests/server/`.
