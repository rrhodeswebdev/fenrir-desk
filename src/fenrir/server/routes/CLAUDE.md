# src/fenrir/server/routes/

One FastAPI router per `/api/<area>`, each `router = APIRouter(prefix="/api/<area>")`, registered in `create_app` with `dependencies=[Depends(require_session)]`. A WebSocket router (`/ws/<name>`) is registered without it and calls `check_ws` before `accept()`. Shapes in `docs/contracts.md`.

- Entry points: `rules.py` (Plan 15: list, read, save account rules; pure `staleness`); `data.py` (Plan 16: `GET /api/data`, `POST /api/data/pull`; pure `front_months(instruments, day)` → `{ES, NQ}`, None outside the rollover calendar); `backtests.py` (Plan 14: options, jobs, results, compare, plus `ws_router` for `WS /ws/jobs`; `strategy_glob_ok` vets every strategy glob before `app.state.jobs.expand`; never loads a strategy file); `settings.py` (Plan 24: `GET`/`PUT /api/settings` over the secrets file, only the six `ENV_KEYS`, pure `view`, `env_updates` (mask sent back = unchanged), `has_secrets`; `GET`/`PUT /api/settings/accounts` merging `accounts.yaml`; `repo_env_secrets` read with `O_NOFOLLOW` in the image only; `POST /api/settings/import-repo-secrets` saves those secrets only into empty keys, through `PUT`'s `_save`); `terminal.py` (Plan 13: `WS /ws/terminal`, the Workbench shell; process in `../ptyproc.py`, protocol in `../terminal.py`); `strategies.py` (Plan 23: `GET /api/strategies`; file names only here, `app.state.jobs.describe` loads them in the isolated child).
- Pure vs shell: handlers only parse, check and forward; pure helpers sit at the top of each module. Shared state comes from `request.app.state` (`settings`, `pull`, `jobs`). A WebSocket handler calls `check_ws` before `accept()`, removes any runner listener before its first `await` in `finally`, and hops runner-thread callbacks to the loop with `call_soon_threadsafe`.
- Not here: auth and the app itself (`../`), long-running work (`../pull.py`), rule logic and rule file writes (`src/fenrir/rules/`), coverage (`src/fenrir/data/`).
- Tests: `tests/server/test_<area>_routes.py`; the terminal in `test_terminal_ws.py`.
