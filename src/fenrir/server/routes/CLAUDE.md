# src/fenrir/server/routes/

One FastAPI router per `/api/<area>`, each `router = APIRouter(prefix="/api/<area>")`, registered in `create_app` with `dependencies=[Depends(require_session)]`. A WebSocket router (`/ws/<name>`) is registered without it and calls `check_ws` before `accept()`. Shapes in `docs/contracts.md`.

- Entry points: `rules.py` (Plan 15: list, read, save account rules; pure `staleness`); `data.py` (Plan 16: `GET /api/data`, `POST /api/data/pull`; pure `front_months(instruments, day)` → `{ES, NQ}`, None outside the rollover calendar); `backtests.py` (Plan 14: options, jobs, results (`?limit=1..100` reads only the newest-written files), compare, plus `ws_router` for `WS /ws/jobs`; `strategy_glob_ok` vets every strategy glob before `app.state.jobs.expand`; never loads a strategy file); `settings.py` (Plan 24: `GET`/`PUT /api/settings` over the secrets file, only the six `ENV_KEYS`, pure `view`, `env_updates` (mask sent back = unchanged); `GET`/`PUT /api/settings/accounts` merging `accounts.yaml`); `terminal.py` (Plan 13: `WS /ws/terminal`, the Workbench shell; process in `../ptyproc.py`, protocol in `../terminal.py`); `strategies.py` (Plan 23: `GET /api/strategies`; file names only here, `app.state.jobs.describe` loads them in the isolated child); `arming.py` (Plan 23: `GET /api/arming`, `GET /api/arming/accounts`, `POST /api/arming/arm` and `/disarm`; every rule is in `fenrir.live.arming.decide`; the file is hashed, never loaded; list → decide → insert under one `BEGIN IMMEDIATE`; a live confirm counts only when it echoes the summary's `strategy_hash`, `rules_hash` and `dll_on`; disarm journals a `"halt"` `disarmed` row and deletes the row in one transaction (`arming.disarm`); never add a CLI or session-free path to these); `live.py` (Plan 21: `GET /api/live/status` is `async` and returns `app.state.live.status()` from memory, no database; `GET /api/live/journal?account=&day=` is sync (threadpool) on its own `journal.open_ro` connection, never the hub's, `[]` while `fenrir.db` does not exist; `POST /api/live/kill` and `/resolve` are `async` and only await `app.state.live.kill()` / `resolve(account)` (KeyError → 404), so they run under the hub lock; UI-only, never add a CLI or session-free path to them).
- Pure vs shell: handlers only parse, check and forward; pure helpers sit at the top of each module. Shared state comes from `request.app.state` (`settings`, `pull`, `jobs`, `live`, `addon`). A WebSocket handler calls `check_ws` before `accept()`, removes any runner listener before its first `await` in `finally`, and hops runner-thread callbacks to the loop with `call_soon_threadsafe`.
- Not here: auth and the app itself (`../`), long-running work (`../pull.py`), rule logic and rule file writes (`src/fenrir/rules/`), coverage (`src/fenrir/data/`).
- Tests: `tests/server/test_<area>_routes.py`; the terminal in `test_terminal_ws.py`; `live.py` in `tests/live/test_live_routes.py`.
