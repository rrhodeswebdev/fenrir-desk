# web/src/backtests/

The parts of the Backtests page (`../routes/backtests.tsx`) that talk to the backtests API (`docs/contracts.md` "Plan 14 — backtest jobs API").

- Entry points: `RunForm.tsx` (`RunForm`: ticks strategies × accounts × contracts from `GET /api/backtests/options` (query `['backtests', 'options']`) and posts them to `POST /api/backtests/jobs`, then shows the new job id; no contract ticked sends `contracts: null`, every contract of each strategy's market; a 4xx shows via `errorText`; a failed options refetch shows above the form; ticks a refetch removed are dropped by `withinOptions`, never posted). Pure helpers `toggle`, `jobBody`, `withinOptions`, `canRun`, `postJob` and the stateless `RunFormView` are exported for tests.
- `JobList.tsx` (`JobList`: one row per item of the latest 5 jobs from `GET /api/backtests/jobs` (query `['backtests', 'jobs']`, never refetched); status as `StateText`, an item's error text under it in the row, a running item's whole percent, a done item's Report link; a line when live updates stop). `progressText` and the stateless `JobListView` are exported for tests.
- `Compare.tsx` (`Compare`: By account / By strategy tabs over `GET /api/backtests/compare?view=` (query `['backtests', 'compare', view]`, refreshed by the socket's invalidation); one table, a row group per server group, rows in server order (ranked by tuning only, never re-sorted here); tuning then hold-out figures (P(pass+payout), pass rate, net per attempt, microscalp flags), hold-out in Slate, a microscalp count above 0 and the hold-out gap in Ember; a tuning-only report shows dashes for hold-out). Pure `identity`, `pct`, `money`, `figures`, `compareKey` and the stateless `CompareView` are exported for tests.
- `useJobsSocket.ts` (`Job`/`JobItem` types; `useJobsSocket(enabled)`: opens `/ws/jobs` once the GET has landed and upserts each pushed job into `['backtests', 'jobs']` through `receiveJob`, which invalidates `['backtests', 'results']` and `['backtests', 'compare']` when one of a job's items finishes; no polling, no reconnect: a reload resumes). A new job reaches the list through the socket (the runner notifies on submit), so the run form invalidates nothing. Pure `upsertJob`, `finished`.
- `Report.tsx` (`Report`/`Period` types for `GET /api/backtests/results/{key}`; `ReportView`: run facts incl. `dll_on`, tuning and hold-out side by side with gross and net per attempt and the overlap note, params, then per period the days-to-pass histogram (HTML bars, text alternative in `aria-label`) and up to 6 `lightweight-charts` equity samples, each captioned in words; the canvas is `aria-hidden`). Pure helpers: `charts.ts` (`bins`, `histogramText`, `equitySeries`, `equityCaption`, `outcomeColor`, `chartOptions`: colours read from the `--chart-*`/`--rule` tokens at mount, dark only) and `format.ts` (`pct` and `money` (null → dash) from `Compare.tsx`, `num`, `paramText`).
- Not here: the page shell and routes (`../routes/backtests.tsx`, `../routes/backtest-report.tsx`), grid expansion and validation (the server).
- Tests: `RunForm.test.tsx`, `JobList.test.tsx`, `Compare.test.tsx`, `useJobsSocket.test.ts`, `charts.test.ts`, `format.test.ts` (Vitest, node env, `renderToStaticMarkup`; `fetch` stubbed for the POST body; `receiveJob` against a real `QueryClient`); the report page render is `../routes/backtest-report.test.tsx` (charts only draw in an effect, so a static render needs no mock).
