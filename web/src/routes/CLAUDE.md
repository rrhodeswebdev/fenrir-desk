# web/src/routes/

One file per UI page. Each exports `<page>Route` built with `createRoute({ getParentRoute: () => rootRoute, path, component })`, importing `rootRoute` from `./root`.

- Entry points: `root.tsx` (`rootRoute`: the index rail shell, the not-found page, and the "Session expired" line shown while any query's last error is a 401); `../router.tsx` assembles the tree, so add a new route there. A later task replaces a stub's `component` and nothing else in `router.tsx`.
- Pages: `/` workbench (xterm.js over `WS /ws/terminal`: pure `inputFrame`/`resizeFrame`/`closeLine`, theme read from the CSS tokens at mount, frames typed while connecting queued and sent after the first resize, fit add-on + `ResizeObserver` sending resize frames, a disconnect line on close, no reconnect; the 'Latest backtest' pane beside it: `GET /api/backtests/results?limit=1` (`latestQuery`: key `['backtests', 'results', { limit: 1 }]`, polled every 3 s by `latestPollMs` because `/ws/jobs` never sees a CLI run; stops on a 401; no retry, the next poll is one) as facts, Compare's figures for tuning and hold-out, and a Full report link), `/rules` (rule files with staleness; `?account=<id>` opens that file in the field-by-field editor beside the list: draft state only through `setIn`, Save → `PUT`, 422 errors under their input by `loc` plus a summary; every schema field, including `funded.scaling` tiers with Add/Remove), `/data`, `/backtests`, `/backtests/$key` (`backtest-report.tsx`: the report for that cache key, query `['backtests', 'results', key]`, no retry on a 404, rendered by `@/backtests/Report`), `/strategies` (armed accounts from `GET /api/arming` with a Disarm each behind a Red-bordered AlertDialog; the arm form: strategy file, a backtest's account type and contract (from the file's current-hash `reports`), NinjaTrader account from `GET /api/arming/accounts` (query `['arming', 'accounts']`, no retry; a text input when NinjaTrader is down), mode, phase, and for sim/live `start_balance`/`peak_balance` prefilled with that account's balance now; a `409 needs_confirmation` opens the Ember-bordered live AlertDialog with the tuning summary, the start and peak balances sent with the liquidation level they give, `dll_on`, the hashes (12 characters, the full hash in a `<details>`) and the hold-out gap in Ember, and only its Arm live sends the confirm POST (`confirmBody` echoes `strategy_hash`, `rules_hash`, `dll_on`); a stale confirm shows the new summary and focuses Cancel, never re-posting on its own; arm, confirm and disarm POSTs are single-flight (`useSingleFlight`), and a disarm's `{ok: false}` shows as an error; refusal codes in words by `armErrorText`; then the strategy files with params, load errors and the latest backtest. Pure helpers `targets`, `armBody`, `confirmBody`, `refusal`, `needsConfirmation`, `armErrorText`, `armedAt` and `SummaryFacts` are exported for `strategies.test.tsx`), `/live` (`GET /api/live/status`, query `['live', 'status']`, polled every 2 s by `statusPollMs` with no retry, through errors but not after a 401, and treated as absent while its last read failed; the top strip and kill switch from `@/live/strip`; the kill is a mutation keyed `['live', 'kill']` (90 s timeout), read back with `useMutationState` so leaving and returning mid-kill keeps Kill all disabled; its answer or request error, stamped with the New York time it was pressed, in the body; parts in `../live/`), `/live/journal` (`live-journal.tsx`), `/settings` (two forms like the rules editor, each sending only edited keys: the six secrets-file settings, secrets shown as their masks; per-account `eval_price` and `dll_on`; an Ember alert listing `nested_git` when the terminal left a `.git` in the repo). Each renders `<Page title strip>` from `@/components/page`.
- Data: `useQuery({ queryKey: ['<area>', ...], queryFn: () => apiFetch(...) })` from `@/api`; mutate with `useMutation` and invalidate the area's keys. No `fetch` outside `../api.ts`. Show errors with `pageError(e)` (null for a 401: the shell's banner reports it).
- Not here: shared components (`../components/`).
- Tests: `root.test.tsx` renders each path with `renderToString` (no DOM); a page with data gets its own `<page>.test.tsx` that seeds the query cache with `setQueryData`; a page's pure helpers are exported from its file and tested in `<page>.test.ts` (e.g. `data.test.ts`: roll rows, poll interval); browser flows in `web/e2e/` (#38).
